# If I Were A Publisher PM Testing A Vietnamese Studio

Testing a Studio is not the same as delegating a task. A lot of bad deals begin because the Publisher thinks they are testing a Studio while actually just giving them work.

The 6-week test logic - Week 0 - define scope, success, failure, ownership. Week 1 - build core, instrument events. Week 2 - check marketability and clarity. Week 3-4 - read Retention, inspect fail points, review economy. Week 5 - decide iterate/kill/scale. Week 6 - write learning, decide next bet.

6-Week Test = Scope -> Build -> Instrument -> Marketability -> Retention Read -> Decision

Score the Studio across six dimensions - Execution Speed, Design Reasoning, Data Readiness, Communication Hygiene, Production Judgment, Learning Behavior. This is more useful than asking whether the first prototype is "good." Rough and thoughtful is very different from rough and confused.

Before the first meeting, the Studio should send - questions they need answered, assumptions they are making, risks they see, smallest test scope recommended, and decisions needed from the Publisher.

After the meeting - what was decided, what was not, who owns each next step, remaining risk, what will be delivered next, and when the next decision happens.

The Studio is not being tested only on the prototype. It is being tested on how it learns.

The best Publisher PMs test Studio maturity, not just output quality. The first project is a test of how the team thinks when the answer is not obvious.
