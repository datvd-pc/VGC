# If I Were Designing A Deal With A Vietnamese Studio

The deal decides what the team learns. A lot of deals share money. The better deals also share learning, or at least make learning visible.

The agreement should cover: IP, source, Data access, milestone logic, soft launch budget, Live Ops responsibility, revert rights, postmortem expectations, and who gets to reuse what later.

> Deal = IP + Data + source + milestone + soft launch + revert + postmortem

Design the deal as a ladder, not a fixed identity:

- **Level 1 - Production Partner:** Studio owns delivery. Publisher owns product direction, Data, UA, decisions.
- **Level 2 - Prototype Partner:** Studio owns delivery plus mechanic exploration and scope proposal. Publisher shares more context.
- **Level 3 - Product Partner:** Studio owns larger product hypothesis, feature prioritization, iteration plan. Publisher shares Data more deeply.
- **Level 4 - Operating Partner:** Studio runs Live Ops, content planning, Data review with Publisher oversight.
- **Level 5 - Strategic Partner:** Both sides discuss IP, co-development, co-publishing, long-term Portfolio planning.

Both sides should know what the next level requires. Progression should be measurable: three clean prototypes earn larger design ownership, reliable event tracking earns more Data access, successful iterations earn more product authority.

Operating clauses to include: milestone definition, build delivery standard, dashboard access level, postmortem format, decision response time, IP and source boundaries, reuse boundaries, escalation path, next-project review criteria.

> No major decision without a written recap.

That one rule protects both sides. It prevents "I thought we agreed" conversations, makes scope changes visible, and creates a trail for learning.

> The goal is to make every deal teach the Studio how to deserve a better one next time.
