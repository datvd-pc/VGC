# Junior Game Designer

Junior Game Designers often know mechanics before they understand behavior. A level is not just something to make harder. It should create clarity, fairness, near-miss, willingness to retry, and a reason to return.

> Good Level Design = clarity + fairness + near-miss + return reason

Learn these before fancy buzzwords: FAR (First Attempt Rate), APS (Attempts per Success), SR (Success Rate), fail-to-retry, fail-to-quit, near-miss, booster value, reward timing, clarity vs difficulty.

> Players do not quit only because a level is hard. They quit when the failure feels unfair, unclear, repetitive, or not worth another try.

Level review checklist: What is the first thing the player should notice? What is the main decision? What mistake is the level teaching? Is difficulty visible before failure? Does the player have a meaningful option? Is the near-miss believable? Is booster placement helpful or manipulative? What would make the player retry vs quit?

The learning loop: Hypothesis -> build -> observe -> Data -> lesson -> next level. Not: Idea -> build -> opinion -> more opinion.

Write one sentence before every level:

> This level is testing whether the player can...

And one sentence after:

> The player failed because...

Common mistakes: adding too many mechanics too early, confusing difficulty with quality, copying a reference without understanding the player promise, ignoring fail-to-retry behavior, tuning by taste only.

AI can help review level notes, compare mechanics, summarize feedback, and detect patterns in fail Data. But the Designer still needs taste, empathy, and understanding of player trust. AI cannot feel the player's frustration for you.
