# If I Were Designing A Deal With A Vietnamese Studio

The deal decides what the team learns.

That is the cleanest way to think about it.

A lot of deals in games are designed to share money.
The better deals also share learning, or at least make learning visible.

If I were designing a deal with a Vietnamese Studio, I would make sure the agreement covered:

- IP;
- Source;
- Data access;
- Milestone logic;
- Soft launch budget;
- Live Ops responsibility;
- Revert rights;
- Postmortem expectations;
- Who gets to reuse what later.

The formula is:

> Deal = IP + Data + source + milestone + soft launch + revert + postmortem

That sounds detailed because it has to be.

Vietnamese Studios are often fast and adaptable. That is valuable. But if the deal is too loose, the Studio may end up with cash and little control. If the deal is too controlling, the Studio may lose the incentive to care deeply.

The best deal sits in between.

It gives the Publisher enough control to protect the investment.
It gives the Studio enough visibility to keep learning and enough freedom to keep moving.

If I were a Publisher, I would not use the same deal structure for every Studio.

- A vendor needs one shape.
- A prototype hunter needs another.
- A reskin Studio needs another.
- An emerging Operator needs another.

The next 2-4 years will not reward generic contracts. They will reward contracts that match the actual maturity and ambition of the partner.

If I were a Studio, I would never sign a deal without understanding what I keep after the launch.
That answer is often worth more than the headline Revenue Share.

I would also design the deal as a ladder, not a fixed identity.

Many partnerships fail because the first contract freezes the relationship. The Studio is treated as a vendor forever, or the Publisher gives too much independence before the Studio has earned it. Both mistakes create frustration.

A ladder is better.

Level one: **Production Partner**.
The Studio owns delivery. The Publisher owns product direction, Data, UA, and final decisions.

Level two: **Prototype Partner**.
The Studio owns delivery plus mechanic exploration, scope proposal, and first-pass design reasoning. The Publisher still owns UA and market validation, but shares more context.

Level three: **Product Partner**.
The Studio owns a larger part of the product hypothesis, feature prioritization, and iteration plan. The Publisher shares Data more deeply and expects the Studio to propose decisions.

Level four: **Operating Partner**.
The Studio can run Live Ops, content planning, Data review, and product improvement with Publisher oversight.

Level five: **Strategic Partner**.
Both sides can discuss IP, co-development, co-publishing, long-term Portfolio planning, and larger financial structures.

Not every Studio needs to reach level five.
But both sides should know what the next level requires.

This is important for Vietnamese Founders because many want better terms before they have built the proof that justifies those terms.

It is also important for Publishers because many want stronger partners without giving them enough visibility to become stronger.

The deal should make progression measurable.

For example:

- If the Studio delivers three clean prototypes with strong communication, it earns larger design ownership.
- If the Studio builds reliable event tracking and postmortems, it earns more Data access.
- If the Studio proposes successful iterations, it earns more product authority.
- If the Studio manages Live Ops reliably, it earns performance upside.
- If the Studio creates original IP with validated traction, it earns stronger IP negotiation.

This is practical.

It reduces emotional negotiation and replaces it with capability milestones.

The deal should also protect both sides from common failure cases.

For Publishers:

- Unclear source access;
- Weak confidentiality;
- Unclear IP reuse;
- Missed milestones;
- Hidden subcontracting;
- No documentation;
- Unclear kill criteria.

For Studios:

- No test feedback;
- No Data visibility;
- No payment protection;
- No credit;
- No reuse rights;
- No postmortem;
- Endless scope changes;
- Vague “maybe next project” promises.

When these issues are not written down, they become relationship problems later.

So I would put operating clauses into the deal:

- Milestone definition;
- Build delivery standard;
- Dashboard access level;
- Postmortem format;
- Meeting note owner;
- Decision response time;
- IP and source boundaries;
- Reuse boundaries;
- Escalation path;
- Next-project review criteria.

These clauses do not need to be complex.
They need to be explicit.

For Vietnam, explicit structure is a gift when used correctly. It reduces misunderstanding, protects trust, and gives young teams a clearer path to maturity.

My prediction:

In the next 2-4 years, the strongest Publisher-Studio deals in Vietnam will not simply offer the highest Revenue Share. They will be the deals that create a visible path from production work to operating ownership.

That path is where real partnership begins.

If I were designing the actual working process around the contract, I would also add one simple rule:

> No major decision without a written recap.

That one rule protects both sides.

It prevents “I thought we agreed” conversations.
It makes scope changes visible.
It creates a trail for learning.
It helps the Studio show professionalism.
It helps the Publisher keep control without micromanaging.

The contract and the workflow should support each other.

If the contract is clear but the workflow is vague, the project still gets messy.
If the workflow is clear but the contract is vague, the relationship still gets risky.

The best setup is both:

- Explicit deal structure;
- Explicit communication habit;
- Explicit review points;
- Explicit path to more responsibility.

That is what I would want if I were building long-term in Vietnam.

The goal is not to make every deal larger.

The goal is to make every deal teach the Studio how to deserve a better one next time.
