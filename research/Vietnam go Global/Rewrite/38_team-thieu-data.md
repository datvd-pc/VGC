# Team Without Data

If you do not have Data, you are probably optimizing by feeling.

Data Work = Instrumentation + Interpretation + Decision

Logging events is not enough. You must read them, and after reading, decide. A team without Data fails through small guesses repeated for too long - the Designer guesses why players quit, the Developer guesses which bug matters, the PM guesses whether the build is ready, the Founder guesses which game deserves more time.

Minimum Data habits to start with

- D1 Retention, D7 Retention
- First-session length
- Level fail rate and retry rate
- Tutorial completion
- Ad engagement, IAP funnel if relevant
- Crash rate, source of traffic

Connect every metric to a decision

- Low Tutorial Completion -> Fix Onboarding before Adding Content.
- High Fail Rate But High Retry -> Pressure May Be Useful.
- High Fail Rate and Low Retry -> Trust May Be Broken.
- Bad CPI But Good Gameplay Metrics -> Creative or Market Promise May Be the Issue.
- Weak D1 -> Do Not Talk Too Early About Long-Term Live Ops.

What decision does this metric support?

If the metric does not change a decision, it is not yet useful enough. Collect Data because it changes action, not because it looks professional.

A Designer who can read Retention is stronger. A PM who can connect Data to decisions is stronger. A Developer who understands event quality is stronger. A Founder who knows the limits of the Data is stronger.

Minimum Dashboard - Retention, Playtime, Fail Rate, Retry Rate, Monetization Signal, Crash Rate. Then ask one question - Metric -> Decision -> Action.

You do not need to become a Data Scientist. But you do need to stop making important game decisions in the dark.
